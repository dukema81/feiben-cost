## 二、单元测试（51 条，`tests/test_unit_core.py`）

### 2.1 标准成本卡（4 条）
- 材料 = Σ 单位用量 ×（1 + 损耗率）× 标准单价
- 人工 / 制造费用 = 标准工时 × 中心费率
- 零用量、零费率、负值输入的边界处理
- 多行 BOM 逐行累加与合计一致

### 2.2 实际成本归集（2 条）
- 材料 + 人工 + 实际工时 × 制造费率（预定分配率法）
- 空数据工单返回全零而不抛异常

### 2.3 约当产量法（6 条）
- 约当产量 = 完工数 + 在制数 × 完工进度
- 单位成本 = 待分配合计 ÷ 约当产量
- 在制成本 = 合计 − 完工转出（守恒）
- 完工进度 0 / 1 / 50% 三档
- 完工数 = 0 时单位成本不外溢

### 2.4 材料差异（3 条）
- 价差 =（实价 − 标价）× 实量
- 量差 =（实量 − 标量）× 标价
- 价差 + 量差 = 实际 − 标准（闭合）

### 2.5 人工差异（2 条）
- 工资率差 =（实率 − 标率）× 实工时
- 效率差 =（实工时 − 标工时）× 标率

### 2.6 制造费用差异（2 条）
- 耗费差 = 实际制费 − 实际工时 × 标准分配率（预定分配率法下与总差异同基）
- 耗费差 + 效率差 = 实际制费 − 标准工时 × 标准分配率（闭合）

### 2.7 差异等级（3 条）
- 阈值分级（正常 / 关注 / 重大）与正负号处理
- 零差异归入正常
- 超阈值触发重大标识

### 2.8 产品差异汇总（1 条）
- 五维之和（价差 + 量差 + 工资率差 + 效率差 + 耗费差）= 实际总成本 − 标准总成本，`checkDiff = 0.00`

### 2.9 阶梯（顺序）分摊（8 条）
- 按 `alloc_order` 升序执行
- 分入量累加到下游中心后再整体摊出
- 禁止回分（只能分给顺序更大的中心）
- 末位中心吸收取整尾差
- 分摊守恒：`baseTotal = allocatedTotal`，`checkDiff = 0.00`
- 空规则、零基数、无下游中心三种边界

### 2.10 预算闸口（3 条）
- 执行率 < 90% 正常
- ≥ 90% 预警、> 100% 超支
- > 110% 阻断提交（`block_rate`）

### 2.11 业务闸口（9 条）
- 工单：未领料不可报工、未完工不可核算、已完不可重开
- 费用：待审批不可入账、已批准不可改单、驳回可回退
- 结账：待审批单据 / 未完工工单 / 未执行分摊三闸口分别拦截，全部满足才可结账

### 2.12 权限矩阵（5 条）
- 7 角色 × 20 权限的 `can()` 判定
- 生产统计可提交但不可审批费用
- 成本会计可审批、不可改主数据
- 只读角色全部写操作拒绝

### 2.13 工具函数（3 条）
- `q2` 两位小数四舍五入（含 0.005 边界）
- `safe_num` 空值 / 非法值归零
- `cur_period` 期间格式 YYYY-MM

## 六、核心口径验证数据

### 6.1 阶梯分摊守恒（2026-10 期间）

```
归集基数合计   baseTotal      = 146500.00
已分摊合计     allocatedTotal = 146500.00
差额           checkDiff      = 0.00
```

辅助中心按 CC201(1) → CC202(2) → CC203(3) 顺序全额摊出，生产中心 CC101/102/103（顺序 5）承接后再向下摊，管理中心与销售中心作为末位吸收方，尾差归末位，保证总额分毫不差。

### 6.2 差异五维闭合（5 个产品抽检）

```
价差 + 量差 + 工资率差 + 效率差 + 耗费差 = 实际总成本 − 标准总成本
全部 5 个产品 checkDiff = 0.00
```

取整尾差由服务层归入材料量差（`resid` → `qtyVar`），保证前端展示的五项相加严格等于总差异，不出现 ±0.01 级漂移。

### 6.3 结账三闸口实测

| 场景 | 接口返回 | 结果 |
|---|---|---|
| 有 2 张待审批费用单 | 「结账闸口：仍有 2 张待审批费用单，请先处理」 | 拦截 |
| 有待完工工单 | 「结账闸口：仍有 N 张工单未完工」 | 拦截 |
| 未执行分摊 | 「结账闸口：本期尚未执行辅助费用分摊」 | 拦截 |
| 三条件满足 | `{"ok": true}`，期间状态 → 已结账 | 放行 |
| 结账后写工单 / 费用 / 分摊 / 预算 | HTTP 409 | 拦截 |

## 八、已知限制

1. HTTP 明文访问，生产环境建议加 HTTPS 与来源白名单
2. 口令以 SHA-256 加盐存储，未升级到 PBKDF2 / bcrypt
3. 单机 SQLite，未做多实例读写分离；SQLite 已开启 WAL，单机并发满足中小制造企业规模
4. 报表为实时计算，未做物化视图缓存；数据量超过十万级工单时建议加汇总表
5. 差异阈值目前为全局规则，未实现按产品 / 中心分级配置（规则表已预留字段）
